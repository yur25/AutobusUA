# Аудит тестування лабораторної 3

**Дата:** 2026-11-21
**Обсяг:** відповідність структури репозиторія [Spec 03](../specs/03-testing.md),
виконання критеріїв приймання та перевірка, чи пропускають зелені тести
підтверджені реальні дефекти.

Перед аудитом повторно перечитано [Specification Template](../../standards/spec-template.md),
[Verification checklist](../../standards/verification-checklist.md) і
[Definition of Done](../../standards/definition-of-done.md). Файлу `spec-format.md`
у репозиторії немає; формат специфікацій визначено доступним шаблоном.

## Відповідність структурі специфікації

| Вимога | Фактичний стан | Оцінка |
|---|---|---|
| Unit-тести поруч із класами | 7 файлів `*.spec.ts` розташовані поруч із кодом у `src/common/` та `src/modules/`; `CarriersService` створюється напряму з рукописними фейками | Відповідає |
| Integration-тести з реальною БД | `tests/integration/critical-path.integration.test.ts` підключається до PostgreSQL і відмовляється працювати не з `autobusua_test` | Відповідає |
| E2E-тести окремим процесом | Два файли у `tests/e2e/`; основний сценарій запускає зібраний застосунок окремим процесом, обидва набори перевіряють тестову БД | Відповідає |
| Єдина команда тестування | `make test` піднімає Compose PostgreSQL, застосовує тестові міграції, потім запускає unit, integration та E2E; команди видалення БД у цілі немає | Відповідає |
| Окреме мутаційне тестування | Stryker налаштований лише на чотири критичні сервіси та пов'язані unit-тести; survivors мають класифікації у звіті | Відповідає |

Структурних відхилень від Spec 03 не виявлено. Розташування smoke-тестів у
`tests/e2e/` відповідає поділу наборів за рівнем.

## Критерії приймання

| Критерій | Повторна перевірка | Результат |
|---|---|---|
| **AC-1** — 100% логічних гілок `CarriersService` | `make coverage`: 11 unit-тестів; 100% statements, branches (10/10), functions і lines | Виконано |
| **AC-2** — PostgreSQL integration для репозиторіїв, rollback, конкурентності та idempotency | `make test`: 14 integration-тестів. Перевірено реальну конкуренцію за останнє місце, concurrent idempotency replay, змінений payload, cancellation capacity та rollback записів квитка й idempotency | Виконано |
| **AC-3** — окремий процес і повний HTTP-сценарій | E2E запускає `scripts/start-app.mjs`; сценарій проходить реєстрацію, login, заявку та адмінське схвалення, створення/пошук рейсу, купівлю/перегляд/скасування квитка й рольову відмову. Smoke перевіряє health, readiness, version і DTO-валідацію | Виконано |
| **AC-4** — `make test`, тестова БД та cleanup | Перевірено ціль Makefile, захист міграції від іншої назви БД, integration `afterEach` та E2E `afterAll` cleanup. `make verify` успішно виконав усі набори; PostgreSQL лишається запущеною | Виконано |
| **AC-5** — обмежений Stryker/Vitest і класифікація survivors | Повторний `make mutation`: 403 мутанти, 349 killed, 54 survivors, 0 timeout/no-coverage/errors. Усі 54 survivor IDs зіставлені з класифікаціями у звіті | Виконано |
| **AC-6** — аудит лише після окремої команди | Аудит запущено за прямою командою користувача | Виконано |

Невирішене питання області `Idempotency-Key` для різних ресурсів залишається
відкритим за рішенням користувача й не блокує лабораторну; воно не було
класифіковане як дефект без визначеного контракту.

## Перевірка прогалин, що приховують реальні дефекти

Перевірено купівлю й скасування квитків, конкуренцію, транзакційні rollback,
idempotency, auth/role guards, bootstrap admin, PostgreSQL помилки, видимість
рейсів і повний E2E-життєвий цикл.

**Підтверджених прогалин, де зелені тести пропускають реальний дефект, не
знайдено.** Топ-3 не сформовано, щоб не представляти непідтверджені ризики як
дефекти. Зокрема, потенційний шлях помилки під час отримання DB connection
перевірено разом із `HttpExceptionFilter`: відомі помилки доступності
PostgreSQL перетворюються на sanitized `503`.

## Перевірки та висновок

- `make coverage` — 11/11 unit-тестів, branch coverage `CarriersService`
  100% (10/10).
- `make mutation` — 403 mutants; 349 killed, 54 survivors. Кожен survivor ID
  присутній серед класифікацій у [звіті мутаційного тестування](./03-mutation-testing-report.md).
- `make verify` — успішно пройшли format check, lint, typecheck, build,
  81 unit, 14 integration та 3 E2E тести.
- `git diff --check` — помилок whitespace немає.

Під час аудиту production-код і тести не змінювалися.
